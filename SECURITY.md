# SAP SAN — аудит безпеки (2026-08-18)

## Що знайдено

**1 критичний секрет у клієнтському коді:** REST URL + токен бази
Upstash Redis лежали відкритим текстом у `js/config.js`
(`redisUrl` / `redisToken`) і використовувались напряму з браузера
в `js/data.js` (`fetchFromRedis()`, `fetch(..., { headers: { Authorization: 'Bearer '+token } })`).

Це статичний сайт без сервера — увесь JS іде в браузер гостя як є.
Токен був видимий будь-кому через «переглянути код сторінки» на
кожному завантаженні сайту, а сам файл `js/config.js` доступний і
напряму (наприклад, через `raw.githubusercontent.com`), оскільки
репозиторій публічний.

Токен потрапив у репозиторій 2026-08-12 і був публічним щонайменше
з 2026-08-16. **Вважайте його скомпрометованим незалежно від
будь-яких змін коду** — видалення з файлу не відкликає те, що вже
було доступне.

Більше нічого схожого на секрет (API-ключі, паролі, приватні ключі,
JWT, дані БД тощо) в проєкті не знайдено — перевірено весь HTML/CSS/
JS/JSON, `.github/workflows/`, `tools/*.js`, `package.json`,
документацію (`README.md`, `API.md`, `BOT_PROMPT.md`,
`CONTENT_REQUEST.md`).

**Пов'язана, але окрема проблема (не в цьому репозиторії):** живий
`GET {apiBase}/content` бота (`sapsanbot.vercel.app`, окремий
проєкт) віддає посилання на фото виду
`https://api.telegram.org/file/bot<ТОКЕН>/photos/...` — токен
Telegram-бота теж торчить у відкритому вигляді в публічній
відповіді API. Виправити це можна лише на боці бекенду бота
(інший репозиторій), тут лише фіксується як знахідка.

## Що зроблено в цьому репозиторії

- З `js/config.js` видалено `redisUrl` / `redisToken` / `redisKey`.
- З `js/data.js` видалено `fetchFromRedis()` і пряме звернення
  браузера до Upstash. Пріоритет джерела контенту спрощено до
  `{apiBase}/content` → вбудований контент — той самий шлях, що
  й був запасним, тож функціональність сайту не змінилась: дані
  й далі приходять через API бота, просто без «швидкого» прямого
  читання з Redis із браузера.
- В `.gitignore` додано `.env`, `.env.local`, `.env.*.local`.
- Додано `.env.example` (без реальних значень).

## Чому НЕ `process.env` у цьому репозиторії

Цей сайт (`sap-san`) — статичний HTML/CSS/JS, який деплоїться на
**GitHub Pages** через `.github/workflows/pages.yml` (звичайний
`rsync` файлів, без збірки й без серверного рантайму). Тут немає
жодного місця, де `process.env` міг би виконатися — немає ні
серверного коду, ні Vercel-функцій, ні збірки, яка б підставляла
змінні в код. Секрет у статичному JS-файлі однаково потрапить у
браузер гостя незалежно від того, звідки він узятий на етапі
збірки, — сама проблема не в тому, «звідки» жорстко закодоване
значення, а в тому, що воно взагалі виконується в браузері.

**Правильна архітектура:** запит до Upstash має виконуватись на
сервері, а не з браузера. Найпростіший шлях — те, що вже частково
є: бот (`sapsanbot.vercel.app`) — це окремий Vercel-проєкт із
serverless-функціями. Токен Upstash має жити як `process.env`
у **тому** проєкті (`UPSTASH_REDIS_REST_URL`,
`UPSTASH_REDIS_REST_TOKEN`), а `/api/content` там же — читати
Redis на сервері й віддавати сайту вже готовий JSON. Сайт це й
робить зараз через `{apiBase}/content` — після цієї правки він
просто ніколи не звертається до Redis напряму.

## Що зробити прямо зараз (не терпить відкладання)

1. **Обертати (ротувати) Upstash REST-токен.** У консолі Upstash —
   Redis Database → Details → REST API → Reset Token (або
   рівнозначна дія). Старий токен уже публічний, новий видавати
   тільки після цього.
2. Новий токен вписати **лише** як змінну середовища
   `UPSTASH_REDIS_REST_TOKEN` (+ `UPSTASH_REDIS_REST_URL`) у Vercel
   проєкту бота (`sapsanbot.vercel.app`) — Project → Settings →
   Environment Variables. **Не** повертати його в цей репозиторій
   і не в будь-який інший клієнтський JS.
3. Якщо в Upstash можна видати окремо **read-only** токен (замість
   повного read-write) — використати саме такий для `/api/content`,
   за принципом мінімальних прав.
4. Попросити розробника бота перевірити той-таки момент із
   Telegram-токеном у посиланнях на фото (див. вище) — це вже
   стосується не цього репозиторію, а бекенду бота.

## Vercel Environment Variables — точний список

Це **не** стосується репозиторію `sap-san` (тут немає Vercel-
проєкту). Змінні нижче потрібно додати в **проєкт бота**
(`sapsanbot.vercel.app`) → Settings → Environment Variables:

| Variable | Призначення |
|---|---|
| `UPSTASH_REDIS_REST_URL` | REST endpoint бази Upstash Redis (новий, після ротації) |
| `UPSTASH_REDIS_REST_TOKEN` | REST-токен бази (новий, після ротації) |

Жодних нових Environment Variables у самому `sap-san` додавати не
потрібно — у репозиторії не лишилось коду, який би їх читав.
