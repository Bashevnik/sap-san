# SAP SAN — інтеграція Telegram-бота з сайтом

## Хто я і що роблю

Я роблю Telegram-бота, який працює **адмінкою для сайту бази відпочинку
SAP SAN**. Сайт уже готовий, задеплоєний і його веде інша людина —
дизайн і верстка не мої. Моя зона — бекенд і бот.

Ключова вимога замовника: **змінив у боті → одразу видно на сайті.**

## Доступи

Репозиторій сайту (публічний, клонується без токена):

```bash
git clone https://github.com/Bashevnik/sap-san.git
cd sap-san
git checkout dev        # працюю ТІЛЬКИ тут
```

- **Читати** може будь-хто — репо публічне.
- **Пушити** — потрібно, щоб власник додав мене в
  *Settings → Collaborators*. Якщо доступу немає, роблю форк і надсилаю
  Pull Request у гілку `dev`.
- Прод-сайт: `https://bashevnik.github.io/sap-san/`
- Моя гілка онлайн: `https://bashevnik.github.io/sap-san/dev/`

Бекенд бота живе **в окремому репозиторії** — цей репо тільки для сайту.

## Перше, що зробити

Прочитай у репозиторії, саме в такому порядку:

1. **`API.md`** — повний контракт між сайтом і моїм бекендом. Головний документ.
2. **`js/config.js`** — єдиний файл сайту, який я маю право змінювати.
3. **`js/data.js`** — еталонна форма даних. Читати як зразок, **не редагувати**.
4. **`tools/mock-api.js`** — робоча реалізація контракту на чистому Node.
   Це готовий приклад того, що має віддавати мій бекенд.

## Як влаштований сайт

Статика: HTML + CSS + vanilla JS. **Без збірки, без npm, без фреймворків.**
Просто відкривається з будь-якого статичного хостингу.

### Сторінки

| Файл | Що це |
|---|---|
| `index.html` | Головна |
| `houses.html` | Список будиночків |
| `house.html?id=…` | Сторінка одного будиночка |
| `pool.html` | Басейн |
| `gallery.html` | Фотогалерея |
| `rules.html` | Правила та FAQ |
| `contacts.html` | Контакти й карта |
| `booking.html` | Дві форми заявок |

Сторінка будиночка **одна на всіх** — картка обирається через `?id=`.
Додав будиночок у базу — сторінка зʼявилась сама, HTML створювати не треба.

### Скрипти

| Файл | Відповідає за |
|---|---|
| `js/config.js` | **МОЯ ЗОНА.** Адреса API |
| `js/data.js` | Вбудований контент + завантаження з API |
| `js/images.js` | Автогенерований перелік зображень |
| `js/chrome.js` | Шапка, меню, футер |
| `js/pages.js` | Рендер внутрішніх сторінок |
| `js/app.js` | Головна: прелоадер, анімації, FAQ |
| `js/curtain.js` | Слайдер будиночків |
| `js/reveal.js` | Scroll-анімації |
| `js/booking.js` | Валідація й відправка заявок |

### Життєвий цикл сторінки

```
1. Завантажується js/config.js  → звідки брати дані
2. js/data.js робить GET {apiBase}/content
3. Прийшло за 4 с  → підміняє вбудований контент
   не прийшло/помилка → лишається вбудований, пише warning у консоль
4. SAPSAN.onReady() відпускає всі модулі — вони малюють сторінку
```

**Критично:** сайт **ніколи не має падати** через недоступний бекенд.
Якщо мій API лежить — сторінки лишаються робочими на вбудованому контенті.
Це вже реалізовано, я маю це не зламати.

### Як підмінюється контент

- `settings` — зливається по ключах (можна прислати лише `phone`)
- решта розділів (`houses`, `pool`, `housePricing`, …) — замінюються цілком
- прислати можна **частину** розділів, решта лишиться вбудованою
- змінив `lat`/`lng` → карта і кнопка «Прокласти маршрут» перерахуються самі

### Ціни

| Значення | Що покаже сайт |
|---|---|
| `4000` | `4 000 грн` |
| `0` | `безкоштовно` |
| `null` або немає | `за запитом` |

Якщо тариф ще не узгоджений — шлю `null`. **Вигадувати суму не можна.**

### Зображення

`hero`, `image`, `gallery[]` приймають **slug**, а не URL.
Перелік доступних — у `js/images.js`. Сайт сам підставить потрібну
ширину (640 / 1000 / нативна) через `srcset`.

Приклади: `houses-water-wide`, `house-aframe-terrace`, `house-bedroom`,
`house-living`, `house-kitchen`, `house-bath`, `pool-cabanas`,
`pool-cabanas-wide`, `pool-lounger`, `cabana-lake`, `drink-passion`.

## Запуск локально

Два термінали.

**1. Сайт:**

```bash
npx http-server -p 8950 -c-1
# → http://127.0.0.1:8950
```

**2. Мок-API (поки немає справжнього бекенду):**

```bash
node tools/mock-api.js
# → http://127.0.0.1:8940/api
```

Далі в `js/config.js`:

```js
window.SAPSAN_CONFIG = {
  apiBase: 'http://127.0.0.1:8940/api',
  cacheTtl: 60,
  timeoutMs: 4000
};
```

Відкрий `houses.html` — назви й ціни прийдуть з мок-API. Поміняй ціну
в `tools/mock-api.js`, перезавантаж сторінку — оновиться. Це і є
та поведінка, яку має відтворити справжній бекенд.

## МОЯ ЗАДАЧА

Бот + бекенд, щоб працівники бази **без розробника** могли:

1. додавати, редагувати, видаляти будиночки
   (назва, опис, фото, гості, спальні місця, зручності);
2. міняти ціни: будні, вихідні, вікенд-пакет, свята;
3. редагувати прайс басейну: денний, вечірній, дитячий,
   шезлонги, рушник, халат;
4. міняти посилання на меню ресторану;
5. міняти контакти, адресу, координати, графік роботи;
6. редагувати правила та FAQ;
7. **бачити всі заявки з сайту й міняти статус**
   (нова / підтверджена / скасована).

Заявки з сайту мають **автоматично прилітати адміністратору в Telegram**.

### Ендпоінти

**`GET /api/content`** — весь контент однією відповіддю.
Форма строго за `API.md`. Має відповідати швидко: сайт чекає 4 секунди.

**`POST /api/bookings`** — заявка з сайту.

У payload уже є готове поле **`summary`** — зібраний текст заявки
українською (тип, дати, будиночок або кількість шезлонгів, гості,
імʼя, телефон, коментар). Його можна **переслати в Telegram як є**.

Обовʼязково CORS для домену сайту.

### Захист від спаму

На фронтенді вже стоїть honeypot (поле `company`, до API не доходить),
мінімальний час заповнення 3 с і тротлінг 30 с.

**Це обходиться тривіально.** Серверний rate-limit за IP на `/bookings` —
на мені, обовʼязково.

## ЧОГО Я НЕ ЧІПАЮ

Це чужа робота. Зламаю — зіпсую людині тиждень.

### Заборонено змінювати

```
*.html          усі сторінки
css/*           уся верстка й дизайн
js/chrome.js    шапка, меню, футер
js/app.js       анімації головної
js/curtain.js   слайдер будиночків
js/reveal.js    scroll-анімації
js/pages.js     рендер сторінок
js/data.js      вбудований контент
js/images.js    автогенерований, руками не чіпати
images/*        оптимізовані фото
assets/*        логотип, фавікон
```

### Можна змінювати

```
js/config.js       адреса мого API — ОСНОВНА і, як правило, ЄДИНА правка
tools/mock-api.js  мій же інструмент для тестів
API.md             якщо контракт уточнюється — але спершу узгодити
```

### Якщо потрібна правка в «заборонених» файлах

Наприклад, у контенті бракує поля, і без правки `pages.js` не обійтися.

**Не пушу сам.** Порядок такий:

1. роблю зміну в гілці `dev`;
2. пишу власнику, **який саме файл і навіщо**;
3. чекаю на підтвердження;
4. тільки після цього мерджу.

У `main` **не пушу ніколи** без прямого дозволу.

## Чи треба працювати по черзі

**Ні.** Ми не заважаємо одне одному, бо зони не перетинаються:

| Хто | Файли |
|---|---|
| Власник (дизайн) | `*.html`, `css/*`, `js/app.js`, `js/curtain.js`, `js/chrome.js`, `images/*` |
| Я (інтеграція) | `js/config.js` + окремий репозиторій бекенду |

Я торкаюся **одного файла з трьох рядків**. Конфлікт майже неможливий.

### Протокол синхронізації

Перед початком роботи щоразу:

```bash
git checkout dev
git fetch origin
git merge origin/main      # підтягнув свіжий дизайн до себе
```

Після своїх змін:

```bash
git add js/config.js
git commit -m "інтеграція: адреса API"
git push origin dev
```

Коли інтеграція перевірена — прошу власника влити `dev` у `main`
(або відкриваю Pull Request). **Сам не мерджу.**

Якщо все ж виник конфлікт у `js/config.js` — мій варіант завжди
правильніший, беру свій. У будь-якому іншому файлі — беру версію
власника і питаю.

## Порядок дій

1. Прочитати `API.md`.
2. Запустити сайт + `tools/mock-api.js`, подивитися, як воно працює.
3. **Запропонувати мені схему БД і структуру проєкту — перш ніж писати код.**
4. Узгодити, як зберігаємо контент: одним JSON-документом чи
   нормалізованими таблицями. Головне — щоб `GET /content` віддавав
   рівно ту форму, яку чекає сайт.
5. Далі бот, ендпоінти, сповіщення в Telegram.

## Питання, які варто закрити на старті

**Завантаження фото з бота.** Зараз картинки передаються slug-ами
з готового набору, а нові файли генерує `tools/optimize.js` локально.
Щоб працівники могли заливати фото прямо з Telegram, потрібен третій
ендпоінт: покласти файл у `images/` у трьох ширинах і поповнити
`js/images.js`. У поточний контракт це не входить — узгодити окремо.

**Незаповнені дані.** У сайті свідомо стоять `null` і «уточнюйте»
там, де замовник ще не дав цифр: святковий тариф, дитячий тариф від
5 років, повний перелік правил басейну, політика скасування, умови
з тваринами. Це не баг — це місця, які має заповнити адмінка.
