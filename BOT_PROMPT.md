# Промпт для розробника Telegram-бота

Скопіюй усе, що нижче лінії, і встав своєму Claude як перше повідомлення.

---

## Контекст

Я роблю Telegram-бота, який працює **адмінкою для сайту бази відпочинку
SAP SAN**. Сайт уже готовий і задеплоєний, його пише інша людина —
я його **не чіпаю**, окрім одного конфігураційного файла.

Репозиторій сайту: `https://github.com/Bashevnik/sap-san`

Працюємо у гілці **`dev`**:

```bash
git clone https://github.com/Bashevnik/sap-san.git
cd sap-san
git checkout dev
```

**Спочатку прочитай у репозиторії файл `API.md`** — там повний контракт
між сайтом і моїм бекендом. Це головний документ, усе решта вторинне.
Також подивись `js/data.js` (форма даних) і `js/config.js` (точка
підключення).

## Що вже зроблено на сайті — не переробляй

- 8 сторінок: головна, будиночки, сторінка будиночка, басейн, галерея,
  правила/FAQ, контакти, бронювання
- увесь контент читається через `SAPSAN.onReady()` з єдиного шару даних
- якщо задати `apiBase` у `js/config.js`, сайт бере контент із
  `GET {apiBase}/content`, а заявки шле на `POST {apiBase}/bookings`
- якщо API недоступне — сайт мовчки працює на вбудованому контенті
- фронтенд-захист форм від спаму вже стоїть (honeypot, час заповнення,
  тротлінг)

Тобто **фронтенд чіпати не треба**. Моя робота — тільки бекенд і бот.

## Моє завдання

Зробити бота + бекенд, щоб працівники бази могли **без розробника**:

1. додавати, редагувати й видаляти будиночки (назва, опис, фото,
   гості, спальні місця, зручності);
2. змінювати ціни: будні, вихідні, вікенд-пакет, свята;
3. редагувати прайс басейну: денний, вечірній, дитячий, шезлонги,
   рушник, халат;
4. міняти посилання на меню ресторану;
5. міняти контакти, адресу, координати, графік роботи;
6. редагувати правила та FAQ;
7. **бачити всі заявки з сайту і міняти їхній статус**
   (нова / підтверджена / скасована).

Заявки з сайту мають **автоматично прилітати адміністратору в Telegram**.
У payload є готове поле `summary` — зібраний текст заявки українською,
його можна переслати як є.

Ключова вимога: **змінив у боті → одразу видно на сайті.**

## Технічні рамки

- Хостинг бекенду: Vercel (serverless-функції) — сайт статичний, окремо
- Потрібні мінімум два ендпоінти: `GET /api/content`, `POST /api/bookings`
- Обовʼязково CORS для домену сайту
- `GET /content` має бути швидким: сайт чекає максимум 4 секунди
- Формат відповіді — строго за `API.md`
- Ціни: число → сума, `0` → «безкоштовно», `null` → «за запитом».
  Якщо тариф ще не визначений — шли `null`, не вигадуй суму
- Зображення передаються **slug-ами**, не URL. Перелік доступних —
  у `js/images.js`
- Серверний rate-limit за IP на `/bookings` обовʼязковий:
  фронтендові перевірки обходяться тривіально

## Що зробити першим

1. Прочитати `API.md`.
2. Запропонувати мені схему БД і структуру проєкту, **перш ніж писати код**.
3. Узгодити, як зберігаємо контент: одним JSON-документом чи
   нормалізованими таблицями (мені важливо, щоб `GET /content` віддавав
   рівно ту форму, яку чекає сайт).
4. Далі — бот, ендпоінти, сповіщення в Telegram.

## Коли бекенд запрацює

Єдина правка у файлах сайту:

```js
// js/config.js
window.SAPSAN_CONFIG = {
  apiBase: 'https://мій-бекенд.vercel.app/api',
  cacheTtl: 60,
  timeoutMs: 4000
};
```

Комітю це **тільки в гілку `dev`**, перевіряю, і лише потім пропоную
влити в `main`. У `main` без узгодження не пушу.

## Як перевірити, що інтеграція жива

1. Відкрити `houses.html` — назви й ціни мають прийти з бази.
2. Змінити ціну в боті, перезавантажити сторінку — має оновитись.
3. Надіслати заявку з `booking.html` — має прилетіти в Telegram.
4. **Вимкнути бекенд** і перезавантажити сайт — сторінки мають лишитись
   робочими на вбудованому контенті. Це обовʼязково: сайт не повинен
   залежати від доступності бота.
